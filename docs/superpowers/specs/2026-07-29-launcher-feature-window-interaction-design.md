# 一念启动器与功能窗口交互设计

日期：2026-07-29

## 1. 目标

统一启动器、功能全局快捷键、普通功能窗口、临时工作流和后台任务的生命周期，避免以下体验问题：

- 功能窗口关闭、截图取消或任务失败后意外弹出启动器；
- 点击应用或按启动器快捷键时恢复一批用户没有明确要求查看的窗口；
- 启动器显示期间，全局功能快捷键与启动器单键发生重复触发；
- 关闭最后一个窗口后，一念保持前台激活但没有可见窗口；
- 番茄钟等真实后台任务与普通窗口保留状态混为一谈。

核心原则是“明确呼出、单点恢复、静默结束、焦点归还”。启动器只由用户主动呼出；功能结束不自动返回启动器；后台保留多个功能时，只恢复用户明确选择的一个。

## 2. 适用范围

本设计覆盖：

- 用户手动启动应用与登录项、Finder 中继等后台启动的差异；
- 启动器快捷键、Dock 图标和菜单栏图标的呼出行为；
- 启动器内单键、功能全局快捷键和功能卡片点击；
- 翻译、文字识别、番茄闹钟、每日任务、日历、Markdown、解析工具、剪贴板等普通功能窗口；
- 截图选区、取色、截图倒计时等临时工作流；
- 多个功能窗口的保留、隐藏、恢复和关闭；
- 番茄钟到时等系统主动事件；
- 设置窗口关闭和最后一个普通窗口关闭后的焦点归还。

钉图、截图浮动缩略图、系统权限面板和 Finder 后台中继不作为普通功能窗口处理。钉图遵循用户明确设置的置顶、跨空间、鼠标穿透和关闭规则，不随普通应用窗口统一隐藏。

## 3. 权威性与旧规格覆盖

本设计是启动器与功能窗口生命周期的最新权威规则。以下旧行为被本设计明确替代：

- `2026-07-20-feature-workspaces-clipboard-translation-ocr-design.md` 中“关闭功能窗口后恢复启动器”；
- `2026-07-24-touch-flow-calendar-design.md` 中“原生关闭恢复启动器”；
- 现有实现中应用重新激活时自动恢复全部未关闭功能窗口；
- 现有实现中最后一个功能窗口关闭且应用处于激活状态时自动显示启动器。

其他与窗口视觉、原生红黄绿按钮、后台任务持续运行、普通窗口原生层级和可访问性有关的既有规则继续有效。

## 4. 交互状态

窗口可见性与功能运行状态必须分开管理。

### 4.1 可见界面状态

- `background`：一念正在运行，但没有普通界面处于前台。
- `launcherVisible`：启动器可见并接收启动器内单键。
- `featureVisible(featureID)`：一个或多个普通功能窗口可见，其中一个是当前关键窗口。
- `transientWorkflow(kind)`：截图选区、取色或倒计时等临时工作流正在接收输入。
- `settingsVisible`：设置窗口可见。
- `attentionRequired(featureID)`：番茄钟到时等需要用户处理的功能窗口主动置前。

钉图不参与以上互斥状态，可独立可见。

### 4.2 功能保留状态

- `inactive`：没有保留窗口内容，也没有后台任务。
- `retained`：窗口当前不可见，但内容、编辑状态或导航位置仍保留。
- `running`：存在真实后台任务，例如番茄钟倒计时或 GIF 录制。
- `attentionRequired`：任务完成、失败或需要确认。

启动器卡片必须使用符合真实含义的状态文案：

- 普通窗口状态保留显示“已保留”；
- 真实后台任务显示“运行中”；
- 需要用户处理显示“需要处理”；
- 不得把所有未关闭窗口统称为“运行中”。

## 5. 入口与事件规则

| 当前场景 | 用户事件 | 结果 |
| --- | --- | --- |
| 应用尚未运行 | 用户从 Dock、Finder 或 Launchpad 手动启动 | 启动应用并显示启动器 |
| 应用尚未运行 | 登录项、Finder 中继或其他后台事件启动 | 后台启动，不显示启动器、不抢夺焦点 |
| 一念在后台 | 按启动器快捷键、点击 Dock 图标或菜单栏图标 | 只显示启动器，不自动恢复任何普通功能窗口 |
| 启动器可见 | 再按启动器快捷键、按 `Esc` 或点击面板外 | 隐藏启动器并归还原应用焦点 |
| 启动器可见 | 按启动器内单键或点击功能卡片 | 隐藏启动器，只显示或执行所选功能 |
| 启动器可见 | 按功能全局快捷键 | 忽略，不触发功能，不发出错误提示音 |
| 启动器隐藏 | 按功能全局快捷键 | 直接显示或执行目标功能，不经过启动器 |
| 多个功能已保留或运行 | 主动打开启动器 | 只显示启动器，各功能继续保留或运行 |
| 启动器选择一个已保留功能 | 按单键或点击卡片 | 只恢复该功能，其他功能继续后台保留 |
| 同一功能已存在 | 再次明确触发该功能 | 复用现有实例并置前，不创建重复窗口、不重置状态 |
| 普通功能窗口关闭 | 点击原生红色关闭按钮 | 关闭该窗口，不显示启动器 |
| 临时工作流完成或取消 | 完成、`Esc` 或取消按钮 | 静默结束，不显示启动器 |
| 设置窗口关闭 | 点击原生红色关闭按钮 | 不显示启动器 |
| 番茄钟到时 | 系统事件 | 只主动显示番茄钟并请求用户注意，不成组恢复其他窗口 |

启动器显示期间，只屏蔽功能全局快捷键。启动器自己的呼出快捷键仍执行关闭启动器的切换行为，标准文本编辑快捷键仍由当前文本输入控件处理。

## 6. 多窗口与应用激活

### 6.1 切换到其他应用

- 普通功能窗口和启动器隐藏；
- 普通窗口状态进入 `retained`，真实后台任务继续 `running`；
- 不调用普通功能窗口的关闭流程；
- 不清空表单、翻译结果、Markdown 内容、任务状态或计时状态；
- 钉图按自身可见性设置继续显示。

### 6.2 重新进入一念

- 点击 Dock 图标、菜单栏图标或按启动器快捷键始终显示启动器；
- 应用激活回调不得自动恢复全部功能窗口；
- 启动器卡片展示保留、运行和待处理状态；
- 用户选择哪个功能，只恢复哪个功能；
- 其他普通功能窗口继续隐藏，不因 `NSApp.didBecomeActiveNotification` 成组弹出。

### 6.3 一念已经处于前台

用户主动呼出启动器时，启动器成为当前交互窗口。普通功能窗口不得使用永久更高的普通窗口层级压住启动器。用户选择功能后启动器隐藏，目标功能窗口置前。

多个普通功能窗口可同时存在，但任何恢复动作都以单个目标功能为单位。已有可见窗口不因恢复另一个窗口被关闭或重建，窗口前后关系继续遵循“当前点击窗口在最前”的原生行为。

## 7. 关闭与焦点归还

任何普通功能窗口、设置窗口或临时工作流关闭后，都不得自动打开启动器。

关闭后按以下顺序处理：

1. 若仍有另一个可见的一念普通窗口，让 AppKit 按原生窗口顺序选择下一关键窗口；
2. 若存在必须立即处理的 `attentionRequired` 窗口，保持该窗口可见；
3. 若没有其他可见普通窗口，隐藏一念并恢复呼出一念前的外部应用焦点；
4. 若原应用已经退出、不可激活或被系统限制，则调用 `NSApp.hide(nil)`，不强行激活其他随机应用；
5. 钉图不计入“普通窗口仍可见”的判断，也不阻止焦点归还。

启动器协调器需要在每次主动呼出启动器或通过全局功能快捷键进入功能前，弱引用或以进程标识记录此前的前台应用。不得长期持有已退出应用对象，也不得在 Finder 后台中继等无激活流程中改变焦点。

## 8. 番茄钟与主动提醒

番茄钟倒计时在窗口隐藏后继续运行。倒计时归零时：

- 倒计时保持 `00:00:00`，不立即重置为默认时长；
- 番茄钟窗口主动显示并置前，请求用户注意；
- 其他保留窗口不随之恢复；
- 启动器卡片显示“需要处理”；
- 用户停止或关闭闹钟后，不显示启动器，并按第 7 节归还焦点。

番茄钟正在响铃时，用户主动打开启动器不能让提醒无提示地消失。番茄钟继续响铃并保持“需要处理”状态，启动器中提供明显入口；用户仍需在番茄钟面板执行停止操作。

## 9. 快捷键可发现性

- 启动器卡片展示启动器内单键，例如 `S`；
- 设置页展示完整功能全局快捷键，例如 `Option + S`；
- 设置页说明“启动器显示时使用单键；启动器隐藏时使用全局快捷键”；
- 修改功能卡片键位时，同步更新对应全局快捷键的主键，并重新注册；
- 注册冲突时保留旧的有效快捷键，明确指出冲突组合；
- 启动器处于文本输入状态时，单键不得抢占文本输入；
- `Command + C`、`Command + V`、`Command + A` 等标准编辑快捷键始终优先交给输入控件。

## 10. 错误与恢复

- 功能执行失败、权限缺失、XPC 超时或用户取消均不得顺带显示启动器；
- 需要用户操作时，仅显示与当前错误直接相关的自定义错误界面或统一权限中心；
- 错误界面关闭后遵循第 7 节焦点归还规则；
- 全局快捷键重复触发正在执行的不可重入操作时，保持当前流程并给出轻量状态提示，不创建第二个流程；
- 应用激活、窗口关闭和异步任务完成事件必须通过统一协调器串行归并，防止同一事件同时执行“恢复窗口”和“隐藏应用”。

## 11. 架构边界

新增或收敛一个主线程隔离的窗口交互协调器，统一负责：

- 启动器显隐；
- 普通功能窗口的保留状态与可见状态；
- 目标功能单点恢复；
- 功能全局快捷键在启动器可见时的门控；
- 此前前台应用记录与焦点归还；
- 番茄钟等主动提醒的优先级。

插件继续负责自己的领域状态和后台任务，不直接决定是否显示启动器，也不直接恢复其他插件窗口。窗口控制器只报告“显示、隐藏、关闭、最小化和成为关键窗口”等事实，由协调器计算后续动作。

## 12. 验收条件

### 12.1 自动化测试

- 启动器可见时，所有功能全局快捷键均不执行，启动器内单键正常执行；
- 启动器隐藏时，全局功能快捷键可从后台立即执行；
- 点击应用、菜单栏图标或按启动器快捷键只显示启动器；
- 用户手动冷启动显示启动器，登录项和 Finder 中继冷启动不显示启动器；
- 应用重新激活不恢复全部功能窗口；
- 多个已保留功能中只恢复用户选择的一个；
- 同一功能重复触发复用同一窗口实例；
- 关闭普通功能窗口、设置窗口以及取消截图或取色均不显示启动器；
- 关闭最后一个普通窗口后隐藏一念并尝试恢复此前应用焦点；
- 番茄钟到时只显示番茄钟，关闭后不显示启动器；
- 钉图不因上述普通窗口操作被隐藏或关闭。

### 12.2 真实 macOS 验收

- 分别从 Finder、Safari、Xcode 等应用验证启动器呼出、关闭和焦点归还；
- 验证 Dock 图标、菜单栏图标、启动器快捷键、启动器单键和功能全局快捷键；
- 验证多个功能保留后切换应用，再只恢复指定功能；
- 验证番茄钟后台倒计时、到时主动显示、停止和焦点归还；
- 验证截图、取色、翻译选区的完成、取消、权限拒绝和服务异常流程；
- 验证钉图在切换应用和呼出启动器时保持自身可见性；
- 验证不同键盘布局、VoiceOver、减少动态效果和降低透明度状态；
- 使用 UI 测试或辅助功能状态确认没有重复窗口、焦点循环或不可见关键窗口。

代码测试通过与真实 macOS 操作验证必须分别记录，不能以单元测试替代窗口、焦点和全局快捷键的实机验收。
