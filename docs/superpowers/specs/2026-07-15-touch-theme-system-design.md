# 触达三主题系统改造设计规格

## 1. 目标与范围

在不改变启动器现有布局、文案、卡片顺序、搜索结构和功能逻辑的前提下，重构主题系统并实现三套视觉主题：

1. 默认高级毛玻璃主题。
2. 黑夜主题。
3. 白天主题。

主题必须彼此隔离，由统一注册表接入。新增内置主题时不得修改启动器组件中的主题分支，也不得复制启动器布局。

本轮包含启动器主面板、品牌区、主题与设置按钮、搜索框、模式标签、功能卡片、状态提示、图标容器、快捷键标签、搜索结果，以及截图标注编辑器对基础语义色的兼容。本轮不重新设计截图编辑器，不改变设置页信息架构，也不增加在线主题下载、第三方主题包或主题编辑器。

## 2. 已有工程约束

- 原生 macOS 应用，SwiftUI 承载内容，AppKit 承载 `NSPanel`、文本输入和系统毛玻璃。
- 部署基线为 macOS 14.0，禁止引入仅在更高系统可用且没有回退路径的 API。
- 主题按钮继续循环切换主题，不改变现有入口和行为。
- 当前工作区已有搜索输入、全局热键和激活策略改动；主题实现不得覆盖或重写这些改动。
- 开启“降低透明度”或“减少动态效果”时，界面必须保持可读且功能完整。

## 3. 主题标识与迁移

`TouchTheme` 使用稳定的新持久化标识：

| Swift case | 持久化值 | 展示名称 |
| --- | --- | --- |
| `defaultGlass` | `default` | 默认 |
| `night` | `night` | 黑夜 |
| `day` | `day` | 白天 |

循环顺序固定为：默认 → 黑夜 → 白天 → 默认。

`ThemeStore` 使用新的 `appearance.theme.v2` 存储键。首次读取不到 v2 时，从 `appearance.theme.v1` 迁移：

| 旧值 | 新值 |
| --- | --- |
| `crystal` | `default` |
| `obsidian` | `night` |
| `amber` | `day` |

迁移成功后写入 v2。未知值、损坏值和缺失主题定义统一回退到默认主题。命令行参数 `--appearance-theme=` 同时接受新旧值，但命令行覆盖不写入用户偏好。

## 4. 架构

### 4.1 文件边界

```text
TouchApp/Appearance/
├── ThemeStore.swift                选择、持久化、迁移、循环
├── ThemeDefinition.swift           语义令牌和值类型
├── ThemeRegistry.swift             内置主题注册与安全查找
├── DefaultGlassTheme.swift         默认主题唯一视觉定义
├── NightTheme.swift                黑夜主题唯一视觉定义
├── DayTheme.swift                  白天主题唯一视觉定义
├── GlassBackground.swift           NSVisualEffectView 材质桥接
└── ThemeInteractionStyles.swift    聚焦、悬停、按下视觉状态
```

`Packages/TouchKit/Sources/TouchCore/Theme.swift` 只保留稳定、可编码、可测试的主题标识及顺序，不依赖 SwiftUI 或 AppKit。

### 4.2 注册表

`ThemeRegistry` 是主题定义的唯一查找入口，具备以下行为：

- 为 `TouchTheme.allCases` 提供一一对应的内置定义。
- 按产品顺序返回可用主题。
- 找不到定义时返回默认主题定义。
- 测试中允许注入不完整注册表，以验证安全回退。
- 启动器视图不得出现 `switch theme` 或按主题名称判断样式。

### 4.3 语义令牌

`ThemeDefinition` 按组件职责拆分令牌：

- `panel`：系统材质、叠加层、环境反射、边框、高光、内外阴影和圆角。
- `search`：默认与聚焦背景、边框、阴影、占位文字、光标和模式选中状态。
- `card`：默认、悬停、按下背景与边框，阴影、位移和缩放。
- `text`：品牌、主文字、次级文字、弱提示、授权、错误、成功状态。
- `icon`：品牌渐变、图标容器、主图标、辅助图标和系统图标处理。
- `shortcut`：胶囊背景、边框、文字和圆角。
- `motion`：动画持续时间、曲线、悬停位移和按下缩放。
- `fallback`：降低透明度时的不透明面板、搜索框和卡片表面。

启动器、搜索结果和标注编辑器只消费语义令牌，不读取主题具体颜色。

## 5. 默认高级毛玻璃主题

### 5.1 视觉定位

轻盈、通透、安静的 macOS 原生玻璃面板，以冰雾白、浅银灰和雾霾蓝为主体，允许右上角或边缘存在极弱暖白反射。禁止浓重蓝紫、大面积蓝紫渐变、霓虹、深色科技感和复杂背景装饰。

### 5.2 核心颜色

| 语义 | 值 |
| --- | --- |
| 主面板玻璃叠加 | `rgba(236, 241, 248, 0.38)` |
| 冰雾白 | `#F4F7FA` |
| 浅银灰 | `#DCE3EB` |
| 雾霾蓝 | `#AEBECE` |
| 冷灰蓝 | `#7F92A6` |
| 暖白反射 | `rgba(255, 224, 205, 0.10)` |
| 主强调色 | `#748CFF` |
| 辅助浅蓝 | `#8EB7EA` |
| 主文字 | `#303846` |
| 次级文字 | `#697687` |
| 弱提示 | `rgba(72, 84, 100, 0.48)` |
| 授权提示 | `#F28B32` |

### 5.3 真实玻璃实现

- `GlassBackground` 使用 `NSVisualEffectView` 的 behind-window blending，让桌面壁纸真实参与合成。
- 使用系统公开材质获得接近 32–48px 的感知模糊和 110%–125% 的感知饱和度；不使用私有 `CAFilter`，也不截取桌面壁纸模拟玻璃。
- 主面板叠加透明度限定在 30%–45%，中心偏冷，暖白反射仅作为局部低透明环境层。
- 面板颜色随系统材质自然吸收壁纸冷暖变化；文字对比依赖语义文字色、适度玻璃叠加和系统外观，不请求屏幕录制权限做壁纸采样。
- 主面板圆角 32px，1px 白色高光边框，底部与右侧叠加极淡冷灰边界。
- 外阴影为 `0 24 64 rgba(44, 59, 78, 0.16)`，并加入 `inset 0 1 0 rgba(255,255,255,0.72)` 的视觉等效高光。

### 5.4 组件

- 搜索框：`rgba(255,255,255,0.26)`，圆角 22px，白色半透明边框；聚焦为 `rgba(116,140,255,0.72)` 细描边和 3px、10% 透明度外环。
- 功能卡片：默认 `rgba(255,255,255,0.28)`，圆角 19px；悬停提升至 38% 并上浮 2px，不发光。
- 品牌图标：仅图标内部使用 `#8EB7EA → #8D8FF5` 小面积渐变。
- 图标容器：`rgba(255,255,255,0.40)`；图标使用 `#6F91C9`、`#7C82E8` 或 `#637185`。
- 快捷键：`rgba(255,255,255,0.34)` 胶囊，边框 `rgba(255,255,255,0.52)`，文字 `#596677`。

## 6. 黑夜主题

### 6.1 视觉定位

沉浸、克制、专业的深灰黑层级，接近 macOS 深色模式和高效开发工具。禁止纯黑铺满、强霓虹、游戏化和蓝紫覆盖整个界面。

### 6.2 令牌

| 语义 | 值 |
| --- | --- |
| 面板渐变 | `#151824 → #0E111A → #090B11` |
| 面板叠加 | `rgba(12,15,24,0.96)` |
| 主品牌 | `#7C6CFF` |
| 高亮蓝 | `#579DFF` |
| 辅助紫 | `#9B70FF` |
| 主文字 | `#F7F8FC` |
| 次级文字 | `#9EA4B5` |
| 弱提示 | `#626878` |
| 分割线 | `rgba(255,255,255,0.08)` |
| 授权提示 | `#FF9A3D` |
| 成功 | `#4ED5A5` |

- 主面板圆角 30px，边框 `rgba(255,255,255,0.09)`，仅边缘保留极弱冷色环境光。
- 搜索框和卡片默认 `#151925`；搜索聚焦使用 `#6C7CFF`，卡片悬停使用 `#1B2030`。
- 卡片边框默认 `rgba(255,255,255,0.07)`，悬停 `rgba(124,108,255,0.45)`。
- 图标容器使用 `#23284B → #33275C` 的局部深紫蓝层，图标为 `#8A86FF` 或 `#69A6FF`。
- 快捷键背景 `#232735`，文字 `#C5C9D6`，边框 `rgba(255,255,255,0.06)`。

## 7. 白天主题

### 7.1 视觉定位

明亮、干净、轻盈的冷白灰办公工具界面，边界主要由层级和柔和阴影形成。禁止纯白铺满、重阴影、泛滥蓝紫渐变和拟物化。

### 7.2 令牌

| 语义 | 值 |
| --- | --- |
| 面板渐变 | `#F9FAFD → #F4F6FA → #EEF2F7` |
| 面板叠加 | `rgba(248,250,253,0.96)` |
| 主品牌 | `#586DFF` |
| 高亮蓝 | `#3F7CFF` |
| 辅助紫 | `#806CFF` |
| 主文字 | `#1D2330` |
| 次级文字 | `#697184` |
| 弱提示 | `#A2A9B8` |
| 边框 | `#E2E6EE` |
| 授权提示 | `#F28A2E` |
| 成功 | `#2EAD82` |

- 主面板圆角 30px，背景使用 96% 冷白灰叠加和白色高光边缘。
- 阴影分为近层 `rgba(27,39,69,0.08)` 与远层 `rgba(27,39,69,0.05)`。
- 搜索框为 `rgba(255,255,255,0.9)`，边框 `#E1E5ED`，聚焦 `#6680FF`。
- 卡片为 `#FFFFFF`、边框 `#E6E9F0`，仅使用轻阴影；悬停上浮 2px。
- 图标容器 `#EEF1FF`，图标 `#5C6FFF`。
- 快捷键背景 `#F2F4F8`，文字 `#687084`，边框 `#E5E8EF`。
- 选中模式文字 `#4F65F6`，底部使用 2px 短线；未选中使用 `#7D8494`。

## 8. 交互与可访问性

### 8.1 状态

- 悬停：卡片背景和边框按主题令牌提亮，上浮 2px。
- 选中：模式标签使用细下划线或局部描边，不使用大面积填充。
- 聚焦：搜索框使用主题聚焦描边和柔和外环。
- 按下：缩放至 0.98，阴影减弱。
- 默认与白天动画为 160–220ms，黑夜为 140–200ms，统一使用 ease-out 或无明显弹跳的柔和 spring。

### 8.2 系统可访问性

- 开启“减少动态效果”时，禁用位移、缩放和 spring，只保留颜色、边框和不透明度变化。
- 开启“降低透明度”时，各主题改用自己的不透明回退表面；默认主题不得退化为低对比透明层。
- 选中状态同时使用形状和文字权重，不仅依赖颜色。
- 主文字在验收背景上的目标对比度不低于 4.5:1，次级文字和重要图标不低于 3:1。
- 键盘焦点必须与鼠标悬停可区分，VoiceOver 标识和现有 accessibility identifier 保持不变。

## 9. 组件改造

### 9.1 启动器

- `LauncherView` 从注册表读取当前 `ThemeDefinition`，将定义传给子视图。
- 主面板增加独立的高光、冷灰边界和环境反射层，但不改变内容布局。
- 主题切换按钮继续调用 `ThemeStore.cycle()`。

### 9.2 搜索框

- `SearchBarView` 使用独立搜索令牌，并维护视觉聚焦状态。
- `SearchQueryField` 接收文字、占位符和光标颜色，移除硬编码白色。
- AppKit 文本代理在开始/结束编辑时同步聚焦状态；不改变中文输入、全选、Tab 切换和键盘路由。

### 9.3 功能卡片

- 使用独立 `ButtonStyle` 管理按下状态，使用 hover 状态管理上浮和背景变化。
- 状态提示色从主题令牌读取；“需要授权”保持橙色语义。
- 插件名称、快捷键、上下文菜单、拖拽和动作闭包完全不变。

### 9.4 搜索结果与标注编辑器

- 搜索结果使用新的主文字、次级文字、选中背景和状态色。
- `AnnotationEditorAppearance` 从当前主题定义派生基础色，不再调用旧 `ThemePalette.palette(for:)`。
- 本轮不改变标注工具布局、画布、导出或截图业务逻辑。

## 10. 测试策略

### 10.1 单元测试

- `TouchTheme` 新顺序和新 raw value 往返。
- 三个旧值分别迁移到正确新值。
- 新值优先于旧值，命令行覆盖优先于持久化值。
- 未知值和不完整注册表回退默认主题。
- 注册表覆盖全部 `TouchTheme.allCases`，且主题 ID 唯一。
- 三套主题的必需语义令牌完整，透明度和动画范围符合规格。
- 降低透明度表面不透明，减少动态效果时位移为 0、缩放为 1。
- `SearchTextView` 正确应用主题文字、占位符和光标颜色，同时保留中文输入与 Command+A 行为。

### 10.2 集成与回归

- 运行 TouchCore 主题测试。
- 运行 LauncherPanel、SearchCoordinator、FeatureArea 相关应用测试。
- 构建 Debug 与 Release，运行部署目标一致性检查。
- 保留并重新验证现有搜索输入、热键和截图标注测试，不把主题改动与无关修复混成一次提交。

### 10.3 视觉 fixture

为 `default`、`night`、`day` 分别生成稳定 fixture。每个主题至少验证：

- 默认状态。
- 搜索框聚焦状态。
- 卡片悬停和按下状态。
- 降低透明度状态。
- 浅色、深色、冷色和暖色桌面背景。

默认主题必须能清楚看到桌面壁纸经过系统模糊后的色彩与明暗变化；如果只呈现固定浅灰或浅蓝，则验收失败。黑夜与白天主题必须保持层次，分别避免纯黑铺满和纯白铺满。

## 11. 完成标准

以下条件全部满足后才算完成：

1. 三套新主题与旧偏好迁移可用。
2. 每套主题定义位于独立文件，启动器视图没有主题名称分支和硬编码主题色。
3. 默认主题使用真实 behind-window 毛玻璃，并明显透出桌面环境色。
4. 搜索框、功能卡片、图标、快捷键、文字与交互状态符合对应主题规范。
5. 降低透明度、减少动态效果、键盘焦点和可读性验收通过。
6. 当前未提交的搜索、热键和激活策略改动未丢失。
7. 相关自动化测试、Debug/Release 构建与部署目标检查通过。
8. 三套主题视觉 fixture 完成并经过实际渲染检查。
